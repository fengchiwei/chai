## 1. 專案定位與目標

- **名稱**：《少年仔、安啦會客室》。
- **服務對象**：以南投縣國中、高中青少年為主要對象；目前屬於**展示／開發中的原型系統**，不是醫療器材、臨床診斷系統或經認證的危機評估工具。
- **核心目的**：透過自然、低門檻的 AI 對話，陪伴青少年表達心事；整理可直接從對話取得的身心線索；遇到安全警訊時使用規則型保護流程；提供在地資源與真人求助選項。
- **互動風格**：參考薩提爾冰山觀點，以溫暖、自然、不預設對方家庭或心理狀態的語氣互動，避免把一般快樂日常過度心理化。
- **展示情境**：2026 南投黑客松。已討論重點為作品完成度、簡報示範、社會影響、技術可行性及創新；實際競賽規定與時程應以主辦單位公告再次核對。

## 2. 技術架構（目前已有的程式）

| 類別 | 目前技術／模組 | 功能摘要 |
|---|---|---|
| 網頁前後端 | Flask、HTML／CSS／JavaScript | 學生聊天頁、後台、資源頁、模擬示範頁 |
| 資料庫 | SQLite；`models/database.py` | 個案／同意資料、工作臺資訊、對話狀態 |
| 對話策略 | `engine/dialogue_policy.py`、`dialogue_ai.py`、`dialogue_reply.py` | 對話階段、模型分析與產生、回覆檢查及本機備援 |

| 資源／轉介 | `engine/referral.py`、`data/nantou_resources.json` | 資源建議、對話狀態、個案分享同意流程 |
| 身心線索 | **v1.3-A 新增** `engine/wellbeing_signals.py` | 對話中六類有原話證據的資訊記錄，不計算量表分數 |

核心 Flask 端點已含 `/api/chat`、`/api/chat/state`、`/api/assessment`、`/api/referral/consent`、後台與模擬情境路由。網站版本和管理者介面仍需做更完整的權限、安全與真實流程驗證。

### v1.3-A：從自然對話擷取六類身心線索（已安裝／已驗收）

- 新增：`engine/wellbeing_signals.py`、`tests/test_wellbeing_v13a.py`。
- `app.py` 增加線索擷取呼叫，結果保存於伺服器端對話狀態的 `wellbeing_signals` 欄位。
- **六類**：`duration`（持續時間）、`sleep`（睡眠）、`daily_function`（生活／上學功能）、`stress_relationships`（人際與壓力）、`safety`（安全線索）、`support_system`（支持系統）。
- 初始值為 `unknown`。**未提及危機 ≠ 已確認安全**；沒有資料時不得推測不存在。
- 只保存具來源的文字線索，**不自動填寫 BSRS-5、PHQ-9、GAD-7 分數，不自動診斷，不改動四級安全分流**。
- 使用者曾以虛構案例測試「最近兩個禮拜睡不好、上課分心、段考壓力」，直接讀取 SQLite 最新對話狀態後，顯示 `VERSION: v1.3-A-evidence-1` 與六類狀態：

|---|---|

| `sleep` | `reported_difficulty` |
| `daily_function` | `reported_impact` |
| `stress_relationships` | `topic_mentioned` |
| `safety` | `unknown` |
| `support_system` | `unknown` |

### v1.3-A.1：安全對話邊界精修（已安裝／已回歸）

- Claude 僅查看了 `dialogue_policy.py`、`dialogue_ai.py`、`triage.py`，提出 P1–P5；我們以完整 Flask 原始碼核對後只實作有根據的保守修正。
- 已修正的重點：
  1. 安全詢問後「沒有，但昨天有想過」不可直接標為已否認。
  2. 否定範圍不能跨標點無限制遮蔽後方警訊，例如「我沒有說謊，朋友說他想死」。
  3. 「爸爸帶我去打我最喜歡的羽球」不應以關鍵字「打我」誤判為家暴。
  4. 減少不當的安全線索種類分類，但不任意調降已確認的危險句型。
- **刻意未合併**：把「同學說他熱到想死」由橙色調整為黃色的提案；需由輔導／心理專業人員覆核語境、處置與誤漏報權衡。
- **P3 重要釐清**：正常 Flask 聊天路徑已有伺服器端 `dialogue_state` 和歷史最高風險的持續保存；不能直接宣稱「24 則歷史截斷必然讓所有會話風險降回綠」。已跑伺服器狀態路徑之長對話回歸；純 history-only fallback、老舊 cookie 重放及交錯使用者情境仍值得獨立整合測試。
- 安裝日誌：`UPDATE PASS: v1.3-A.1 installed; tests passed (one explicit expert-review skip)`，自動備份在使用者 Windows 專案的 `anla_v13a1_backups/20261021_182320_462980`。

### 最新 Flask 網頁實測：羽球情境

虛構輸入：「爸爸今天要帶我去打我最喜歡的羽球，我很期待！」

API 回覆中觀察到：

```json
{
  "model_used": "Google Gemini (gemini-3.1-flash-lite)",
  "show_urgent_help": false,
  "show_support_help": false
}
```

自然回覆確實圍繞羽球與期待，說明當次請求用到 Gemini 且未觸發危機畫面。但 Gemini 加上「喘息空間」「緊繃感」等使用者未提到的心理狀態，顯示仍有**過度心理化**的對話品質問題。另一次出現「這件事我有在聽……如果對方願意這樣做」等通用模板回覆；該次未取得確切 `model_used` 記錄，不應武斷歸咎於連線失敗。

段考＋睡眠困擾的新一輪前端 A/B 測試尚未見使用者貼回完整網頁回覆，不能標記為完成。

## 5. 尚未完成／不得誤稱已完成的功能

1. **v1.3-B 可解釋儀表板**：尚未編寫／安裝。規劃顯示虛構案例的原話證據、六項線索、已知／未知、規則來源、歷史最高風險及相應行動；需獨立授權及避免洩露真實青少年資料。
2. **OpenAI GPT 切換**：目前使用者表示有意測試 OpenAI，但尚未確認 API 帳戶額度、模型名稱與實際請求成功。現有 `dialogue_ai.py` 支援 OpenAI Chat Completions 介面（預設 `OPENAI_MODEL=gpt-4o`），並不代表任何新模型已整合成功。**ChatGPT Plus 不自動包含 OpenAI API 用量；不要推定 GPT API 免費。**
3. **情境一致性**：尚未加入「開心就回應開心、不無端推測壓力」的回覆檢查與充分測試。
4. **誇飾語句**：例如「熱到想死」，如何兼顧不過度警示及不漏掉真實求助，仍需專業覆核與更多測試。
5. **服務韌性**：模型逾時、非 JSON、被安全過濾、兩階段呼叫累計時間、API 額度不足時的備援回覆仍需壓力測試。
6. **提示詞注入防護**：需檢查使用者語句進入模型上下文時的資料／指令邊界；不能依賴模型自律保證。
7. **身分、會話與資料保護**：仍需完整稽核跨使用者隔離、session 生命週期、資料刪除、CSRF、工作臺授權、正式資料儲存／存取與個案同意機制。
8. **完整系統驗收**：包含多輪真實 Flask 路由測試、完整測試套件、真人專業覆核、行動裝置介面與安全應變演練。
