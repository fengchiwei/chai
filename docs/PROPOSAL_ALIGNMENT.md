# 計畫書對照表（v2.7，2026-10-23）

對照《少年仔、安啦會客室》計畫書（南投縣 2026 山城數位黑客松，高中職組），說明每個項目在原型中的實作位置，以及和計畫書寫法不同的地方與原因。

## 一、計畫目標

| 目標 | 實作 | 狀態 |
|---|---|---|
| (一) 可安心使用的 AI 對話支持入口 | 學生頁 `/`；回覆一律由 AI 寫，危險時依審過的安全文字改寫 | ✅ |
| (二) 結合 BSRS-5 的結構化檢核 | 學生頁「身心電力檢核」：BSRS-5 六題＋持續時間、生活影響、壓力來源、支持系統四題（`static/js/checkin.js`、`/api/assessment`） | ✅ v2.7 |
| (三) 危機規則＋AI 語意的四級分流 | `engine/rules.py`、`engine/triage.py`、`engine/dialogue_policy.py`；燈號只升不降，AI 只能往上調 | ✅ |
| (四) 中高風險時啟動真人接手 | 橙紅色自動送出必要安全資訊到工作臺；學生同意後補上身分與完整對話 | ✅ v2.7 |

## 二、服務流程與四級行動

| 計畫書 | 實作 |
|---|---|
| 1. 進入平台：閱讀隱私、安全及使用範圍 | 第一次使用時的資料使用說明，勾選後才能聊天 |
| 2. AI 對話支持 | 四種回覆風格、可自訂陪伴角色、語音輸入與朗讀 |
| 3. 結構化檢核 | 身心電力檢核（約 2–3 分鐘；工作臺顯示實際用時） |
| 4. 危機規則分析 | 固定規則＋AI 語意線索 |
| 5. 四級風險分流 | 綠、黃、橙、紅；學生頁不顯示燈號 |
| 6. AI 支持或真人接手 | 綠：持續陪伴；黃：建議求助並提供字條草稿；橙：停止一般建議、確認安全、自動送出必要安全資訊；紅：停止一般對話、顯示 119／110／1925、自動送出必要安全資訊 |

分流原則「附加題 2 分以上即停止一般支持並啟動真人優先覆核」：附加題 ≥2 分直接升橙色（`engine/triage.py`）。

## 四、安全與倫理設計

| 計畫書 | 實作 |
|---|---|
| 1. 不診斷、不取代心理師 | 系統提示詞禁止；送出前檢查擋下診斷與替學生下結論的回覆 |
| 2. 不提供藥物或醫療處置建議 | v2.7：提示詞明確禁止；送出前檢查（`medical_advice`）擋下吃什麼藥、劑量、停藥等建議 |
| 3. 匿名；真人接手時告知用途、對象與欄位 | 暱稱、學校、信箱皆可不填；同意畫面列出會分享的內容；自動安全通報時學生畫面會說明送出了哪些欄位 |
| 4. 最小必要資料、角色權限、操作紀錄、去識別化統計 | 自動通報只含必要欄位；v2.7 個人帳號＋管理員／輔導人員兩種角色；操作紀錄以雜湊鏈防竄改，管理員可查看；工作臺「去識別化統計」只有數量，少於 3 不顯示確切數字 |
| 5. 原型只用模擬情境與假資料 | `/demo` 30 組、`/explain` 10 組皆為虛構 |
| 6. 正式導入前由合作單位建立 SOP | 屬於導入階段的工作；工作臺通報檢核與 `docs/PROFESSIONAL_REVIEW.md` 可作為討論起點 |

## 六、和計畫書寫法不同的地方

| 計畫書 | 實際 | 原因 |
|---|---|---|
| 部署在 Replit | 程式碼放 GitHub，網站部署在 Render，另有桌面版與手機版 | 推送到 GitHub 就自動更新網站，免費方案可對外公開；兩者都是雲端平台 |
| SQLite 或 Firebase | SQLite，敏感欄位以 AES-GCM 加密 | 資料留在自己的主機，不送到第三方資料庫 |
| JSON 規則引擎 | Python 規則（正規表示式＋判斷邏輯） | 需要處理否定句、引用、誇飾語與跨輪累積，單純的 JSON 關鍵字表做不到；每條規則都有理論代號與自動測試 |
| 示範影片 | `demo_videos` 裡的影片是舊版 | **需要重錄**：舊影片還有 v2.5.9 已移除的「本機回覆模式」，也沒有 v2.7 的檢核畫面與帳號 |
